# معرفی و نقشه معماری پروژه Ebrahimi Inventory / انبارک

آخرین تطبیق با کد: 2026-10-26
تمام مسیرها نسبت به ریشه مخزن هستند. این فایل نقشه ورود به پروژه است؛
برای وضعیت جاری context/projectStatus.txt و برای قواعد دامنه context/businessRules.md را بخوانید.
در اختلاف مستندات و کد، رفتار موجود را از کد بررسی و اختلاف را گزارش کنید؛
تصمیم کسب‌وکار را خودکار برای تطبیق با یک پیاده‌سازی اشتباه تغییر ندهید.

## هدف و محل استفاده

این نرم‌افزار برای استفاده روزمره در مغازه بهداشتی ساختمانی خانواده مهدی
توسعه داده می‌شود. کاربران اصلی کارکنان مغازه هستند و رابط برنامه فارسی و RTL است.
هدف فعلی، مدیریت کالا و قیمت، موجودی انبار، خرید و ورود کالا، مرجوعی فروش،
مشتریان و صدور و چاپ فاکتور است. ابزار باید کارهای روزانه مغازه را ساده‌تر کند
و اتکا به ثبت‌های پراکنده و دفتر کاغذی را کاهش دهد.

هدف آینده، کمک به مدیریت بهتر حساب‌های دفتری است. دفتر حساب، مانده بدهکاری و
بستانکاری، دریافت و پرداخت و حساب تأمین‌کنندگان هنوز پیاده‌سازی نشده‌اند.
فیلدهای تسویه فاکتور و مبلغ پرداختی را با سیستم حسابداری کامل اشتباه نگیرید.
جزئیات حسابداری آینده باید با صاحب پروژه مشخص شود؛ این هدف، مجوز اجرای
خودکار ماژول‌های جدید در یک کار نامرتبط نیست.

## معماری و ابزارها

مسیر اصلی درخواست:
Vue View/Component -> services/*.ts (fetch) -> NestJS Controller -> DTO/Service
-> PrismaService با PrismaPg -> PostgreSQL

- Frontend/: Vue 3، TypeScript، Vite 8، Vue Router و Pinia.
- Backend/: NestJS 12، TypeScript، Prisma ORM 7.10، pg و PostgreSQL.
- رابط: CSS سفارشی با متغیرهای معنایی، Reka UI، آیکون‌های @lucide/vue و Vazirmatn.
- نمودار: ECharts و vue-echarts؛ کلاس‌های Button با CVA، clsx و tailwind-merge.
- وضعیت تجاری عمدتاً داخل viewها با ref/reactive و درخواست API نگهداری می‌شود.
  Pinia ثبت شده ولی stores/counter.ts نمونه اولیه است؛ فروشگاه مرکزی دامنه نیست.
- Element Plus در رابط فعلی استفاده نمی‌شود. کامپوننت‌ها محلی و با الگوی shadcn
  هستند؛ رجیستری کامل shadcn-vue و خط ساخت Tailwind وجود ندارد.
- Backend از ES modules و NodeNext استفاده می‌کند؛ importهای محلی آن پسوند .js دارند.
- ابزارهای بررسی: vue-tsc، ESLint، Oxlint، Prettier، Node test runner در فرانت،
  Vitest و Supertest در بک‌اند. نسخه دقیق و scriptها را از package.json بخوانید.

## نقشه مخزن و منابع اصلی

- package.json و package-lock.json ریشه: وابستگی‌های مشترک/Prisma؛ اسکریپت اجرای
  برنامه و npm workspace orchestration در ریشه تعریف نشده است.
- Frontend/package.json و Backend/package.json: بسته‌ها و فرمان‌های مستقل.
- prisma/schema.prisma: منبع مدل داده PostgreSQL.
- prisma/migrations/: تاریخچه نسخه‌بندی‌شده تغییرات دیتابیس.
- Backend/prisma.config.ts: پیکربندی معمول CLI؛ schema و migrations در ریشه
  و بارگذاری .env ریشه. scriptهای db:* بک‌اند از این فایل استفاده می‌کنند.
- prisma7.config.ts: پیکربندی جایگزین اجرای CLI از ریشه با --config صریح.
- Backend/src/generated/prisma/: خروجی واقعی client مورد استفاده API.
  با generate بازتولید شود؛ دستی ویرایش نشود. generated/ در ریشه را با آن اشتباه نگیرید.
- Backend/src/app.module.ts: اتصال ConfigModule، PrismaModule و controller/serviceها.
- Backend/src/main.ts: prefix برابر api/v1، CORS و ValidationPipe.
- Backend/src/prisma/prisma.service.ts: PrismaClient و اتصال PostgreSQL در چرخه عمر Nest.
- Frontend/src/main.ts: راه‌اندازی Vue و تم؛ alias برابر @ به src اشاره دارد.
- Frontend/src/App.vue: پوسته، منو، نوار بالا، هشدار کمبود موجودی و RouterView.
- Frontend/src/router/index.ts: مسیرهای واقعی و بازیابی اسکرول محتوای اصلی.
- Frontend/src/types/index.ts: قراردادهای TypeScript سمت کلاینت.
- Frontend/src/services/: پوشش API با fetch؛ api.ts آدرس پایه و خطاها را مدیریت می‌کند.
- Postman/: مواد کمکی؛ controller و DTO مرجع قرارداد معتبر هستند.

## سطح API

آدرس پیش‌فرض: http://localhost:3000/api/v1
VITE_API_URL در فرانت می‌تواند آن را تغییر دهد.

| منبع | مسیرها نسبت به /api/v1 |
| --- | --- |
| دسته‌ها | GET/POST /categories؛ GET/PATCH/DELETE /categories/:id؛ GET /categories/:id/products |
| کالاها | GET/POST /products؛ GET/PATCH/DELETE /products/:id |
| وضعیت کالا | PATCH /products/:id/status |
| قیمت کالا | PATCH /products/:id/price و /products/:id/prices |
| تاریخچه قیمت | GET /products/:id/price-history |
| قیمت گروهی | POST /products/bulk-price-update/preview و /products/bulk-price-update |
| گردش | GET/POST /transactions |
| مشتری | GET/POST /buyers؛ GET/PATCH/DELETE /buyers/:id |
| فاکتور | GET/POST /invoices؛ GET/PATCH /invoices/:id |
| فروشگاه | GET/PUT /store-settings |

ValidationPipe دارای transform، whitelist و forbidNonWhitelisted است؛ فیلدهای
اضافی payload پذیرفته نمی‌شوند. ابتدا controller، DTO و service را بررسی کنید.
لیست کالا و تاریخچه قیمت { data, meta } می‌دهند؛ بیشتر لیست‌های دیگر آرایه‌اند.
لیست کالا تا ۱۰٬۰۰۰ رکورد در فرانت دریافت و محلی صفحه‌بندی می‌شود؛ سرویس نیز
پیش از slice داده‌ها را در حافظه فیلتر می‌کند. گردش و فاکتور حداکثر ۵۰۰ نتیجه
دارند. این مسیرها خروجی کامل داده یا صفحه‌بندی مقیاس‌پذیر نیستند.

## مرزهای فعلی

احراز هویت، نقش/مجوز، login و Swagger فعال در برنامه سیم‌کشی نشده‌اند.
وجود وابستگی JWT/Passport/Swagger یا متغیر JWT در نمونه env، اثبات پیاده‌سازی نیست.
محیط هدف، مغازه است؛ شیوه استقرار نهایی، دسترسی شبکه، پشتیبان‌گیری و بازیابی
باید پیش از بهره‌برداری عملی تعیین و بررسی شوند. پشتیبانی آفلاین یا استقرار
آماده تولید را از معماری فعلی فرض نکنید.
